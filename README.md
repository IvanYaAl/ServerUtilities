# MyFirstMCplugin — TradeOrders / ServerUtilities

Готовые плагины для **Paper 1.21.8** (требуется **Java 21**). Лицензия: Apache 2.0 (указание автора обязательно). Автор: IvanYaAl.

## Установка (любая версия)

1. Скачайте нужный `.jar` из этого репозитория (нажмите на файл → **Download raw file**).
2. Положите его в папку `plugins/` вашего Paper-сервера.
3. Перезапустите сервер. При первом запуске в `plugins/TradeOrders/` (или `plugins/ServerUtilities/`) создастся `config.yml` — все цены, комиссии и лимиты настраиваются там.

## Гайд по версиям

### v1.1.0 — `tradeorders-1.1.0.jar` (базовая версия, написана вручную)

Первая рабочая версия плагина TradeOrders.

**Команды:**
| Команда | Описание |
|---|---|
| `/orders` (`/orderboard`) | Доска ордеров игроков — кто что продаёт/покупает |
| `/order create ...` | Создать свой ордер |
| `/order cancel [id]` | Отменить свой ордер (админ может отменить чужой) |
| `/money` | Проверить баланс монет |
| `/buyer` | Меню скупщика — принимает заранее настроенные предметы из конфига |

**Особенности:** монеты начисляются за убийство мобов; права: `tradeorders.admin`.

---

### v1.2.0 — `tradeorders-1.2.0.jar` (обновление с Qwen)

Новое по сравнению с 1.1.0:

1. **Скупщик покупает ВСЕ предметы.** Больше не нужен список в конфиге: любой предмет оценивается автоматически (настройки из `buyer.base-prices` имеют приоритет, остальное — эвристика по типу: блоки, инструменты, еда, зелья; мусор вроде палок стоит копейки). Сканируется весь инвентарь, включая броню.
2. **Магазин сервера `/shop` (`/store`).** GUI на 54 слота с пагинацией (стрелки назад/вперёд). ЛКМ — купить стак, ПКМ — одну штуку. Оплата монетами с баланса; при полном инвентаре товар падает под ноги. Курс персонально «проседает» при массовых покупках одного товара.
3. **Аукцион `/auction` (`/ah`).**
   - `/auction sell <цена>` — выставить предмет из руки (по умолчанию 30 минут);
   - GUI-доска лотов: ЛКМ — ставка +10%, ПКМ — минимальная перебивка;
   - `/auction cancel <id>` — снять лот;
   - автозакрытие: победитель получает предмет, продавец — деньги минус комиссия 5%; офлайн-игрокам всё возвращается через pending-выдачи при входе;
   - состояние лотов переживает рестарт сервера.

### v1.3.0 — `ServerUtilities-1.3.0.jar` (переименован в «всё в одном», с Qwen)

Плагин переименован в **ServerUtilities** и объединил все функции TradeOrders + новые системы. Пакет команд/прав: `serverutilities.*`.

**Всё из 1.2.0 сохранено** (ордера, валюта, скупщик всех предметов, /shop, /auction), плюс:

1. **Топ лидеров `/top`** — рейтинг игроков по заработку/продажам.
2. **Автоскупщик `/autosell [pick]`** — автоматически продаёт выбранный предмет; цены динамические: чем больше предмета продают, тем ниже цена, со временем курс восстанавливается; есть защита от АФК-спама.
3. **Переводы `/pay <игрок> <сумма>`** — перевод монет между игроками с настраиваемой комиссией.
4. **Скорборд** — постоянный скорборд с балансом монет (`scoreboard.enabled` в конфиге).
5. **Безопасный обмен `/trade <игрок>`** — GUI-обмен между двумя игроками с подтверждением (защита от обмана).
6. **Кланы `/clan`:**
   - `/clan create <название>`, `/clan invite`, `/clan join`, `/clan kick`, `/clan leave`, `/clan info`, `/clan list`;
   - **ранги**: лидер → офицер → участник с разными правами внутри клана;
   - **казна**: `/clan deposit` / `/clan withdraw` (права на снятие — у лидера/офицеров).
7. **Авторизация `/reg` `/login`:**
   - `/reg <пароль> <повтор>` — регистрация, `/login <пароль>` — вход;
   - незарегистрированные/незалогиненные игроки заморожены (нельзя ходить/ломать/писать) до входа;
   - пароли хранятся в хэшированном виде; данные аккаунтов переживают рестарт.

### v1.3.1 — `ServerUtilities-1.3.1.jar`

Всё из 1.3.0 **+ улучшение кланов за валюту:**

- **`/clan upgrade`** — только лидер; оплата **из казны клана** (пополняйте через `/clan deposit`; опция конфига `clan.upgrade.pay-from-treasury: false` — платить с личных монет лидера).
- Каждый уровень даёт **+5 слотов участников** (база 10 → ур.2 = 15, ур.3 = 20 и т.д.).
- Цена растёт геометрически: `300 × 1.8^(уровень−1)` → 300, 540, 972, 1750…
- Максимум 10 уровней. Текущий уровень и цена следующего апгрейда видны в `/clan info` и `/clan list`.
- Настройки в `config.yml`: `clan.upgrade.base-cost`, `cost-multiplier`, `member-bonus`, `max-level`, `pay-from-treasury`.

### v1.3.3 — `ServerUtilities-1.3.3.jar` ⭐ актуальная версия

Исправление команд (по сравнению с 1.3.2):

- **Плагин снова загружается.** В `plugin.yml` поле `description` содержало `1.21.8: ...` без кавычек — двоеточие с пробелом ломало YAML (`mapping values are not allowed here`), из‑за чего сервер не загружал плагин и ни одна команда не работала. Эта же ошибка была в 1.3.0–1.3.2.
- **Работают все алиасы и команды с префиксом:** `/orderboard`, `/store`, `/ah`, `/menu`, `/gui`, `/serverutilities:<команда>` — обработчик теперь определяет команду по её имени, а не по введённой метке.
- Убраны конфликтующие алиасы (`reg`→`register`, `login`→`auth`) — `/register` и `/auth` и так являются отдельными командами.
- `api-version` изменён на `'1.21'` (совместимость со всеми сборками 1.21.x).

Проверено на Paper 1.21.8 (build 60): все команды открывают меню / отвечают корректно.

**Рекомендуется к установке именно эта версия.**

## Как обновиться со старой версии

1. Замените старый jar в `plugins/` на новый и перезапустите сервер.
2. Если `config.yml` уже создан со старой версией — новые секции (`shop`, `auction`, `clan`, `upgrade` и т.д.) добавьте вручную, либо удалите старый конфиг и дайте плагину создать новый (балансы игроков в `balances.yml` при этом не теряются — это отдельный файл данных).
3. Данные ордерах, аукционах, кланах и аккаунтах хранятся раздельно и совместимы между версиями 1.3.x.

## Известные ограничения

- Экономика независима от Vault/other economy plugins (монеты — своя внутренняя валюта).
- Тестировалось на Paper 1.21.8; на других версиях API не гарантировано.
